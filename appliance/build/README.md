# Appliance build pipeline

The appliance is a release artifact, not a target-host build.

For v1.0.0 the builder must use a frozen Ubuntu 24.04 LTS x86_64 base, install INetSim and QEMU Guest Agent, run `image-rootfs-prepare.sh`, place `guest-configure.sh` at `/usr/local/src/cape-inetsim-guest-configure`, and then generalize the image before publication.

Before publication, the build guest generalizes its own identity before shutdown: SSH host keys and cloud-init instance state are removed, machine-id is emptied, and temporary DHCP/lease/build state is removed. `verify-artifact.sh` independently rejects a candidate that retains those identities, the deployment-owned `90-cape-inetsim.yaml`, temporary build DNS state, or persistent static/default routing in sealed netplan configuration.

The finished QCOW2 is published outside normal Git history. Update `appliance/manifest.json` with the HTTPS artifact URL and exact SHA-256, change `status` to `published`, and tag the repository release. Deployment refuses unpublished or checksum-mismatched artifacts.

Candidate provenance is generated by the appliance-build workflow as `candidate-provenance.json` and is carried into release preparation from that exact successful workflow run. Do not commit a mutable candidate checksum/run record into the source tree; doing so would immediately make the record stale when the source commit changes.

The image contains no fixed `192.168.200.0/24` assumption. The isolated NIC address and INetSim bind/default DNS address are configured at deployment through QEMU Guest Agent, using the subnet selected by the host planner.

Release-candidate builds are source-bound, not merely appliance-content-bound. After host-side orchestrator or safety-gate changes, rebuild the candidate from the exact new source commit even when the appliance provisioning scripts themselves are unchanged; the release workflow verifies that candidate provenance and source commit match exactly.

The release source tree preserves executable mode on the operator-facing `install` and `bin/cape-inetsim-*` entrypoints so a direct source checkout behaves the same way as the checksum-pinned bootstrap after extraction.
